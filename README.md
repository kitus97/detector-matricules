# ALPR — Automatic License Plate Recognition from scratch

An end-to-end system that reads European licence plates from photographs, built **without any
pretrained detection or recognition model**. Plate localisation and character segmentation use
classical computer vision (OpenCV); character recognition uses a small CNN trained from scratch on
a synthetic dataset generated by the team.

> Computer Vision course project (UPC). Source comments and documentation are in Catalan;
> this README is in English.

```
photo → [1] detector → [2] segmenter → [3] OCR (CNN) → [3b] reader → "M5XSX"
```

## Results

Measured on 108 annotated images (see [Reproducing the results](#reproducing-the-results)).

| Stage | Metric | Value |
| --- | --- | --- |
| Detector | Recall (GT centre inside a candidate) | **98.1 %** (106/108) |
| Detector | Recall (IoU ≥ 0.5) · candidates per image | 79.6 % · ~3.5 |
| OCR | Synthetic validation accuracy | **98.11 %** (epoch 20) |
| OCR | Character accuracy on real crops (positional) | **89.63 %** (311/347) |
| OCR | Character accuracy (edit distance) | 73.69 % |
| System | Fully correct plates (*plate accuracy*) | **31.82 %** (28/88) |

**Where the errors come from.** Attributing every failure to the stage actually responsible
(a reading whose *length* is wrong is a segmentation error, not a classification one):

| Responsible stage | Images | % |
| --- | ---: | ---: |
| Correct reading | 28 | 25.9 % |
| Segmenter — wrong character count | 29 | 26.9 % |
| Segmenter — real plate rejected | 27 | 25.0 % |
| OCR — character confusion | 22 | 20.4 % |
| Detector — not detected | 2 | 1.9 % |

The segmenter is the largest single source of loss (51.9 %), roughly twice the OCR's own
confusions. The two are also coupled: the CNN's accuracy depends heavily on the crop it receives
(see the ablations below).

## How it works

**1 · Detector** (`alpr/detector/`) — the characters of a plate produce an unusually high density
of *vertical edges* in a small region. The pipeline is: greyscale → Gaussian blur → CLAHE →
vertical Sobel → Otsu threshold → horizontal closing (15×3) → connected components → shape filter.
Thresholds are deliberately loose: the goal is maximum recall, letting later stages reject false
positives.

**2 · Segmenter** (`alpr/segmenter/`) — normalises the crop to a common working height (96 px),
corrects skew by fitting a line through the character centroids, binarises adaptively, extracts
external contours, filters them relative to the plate height, and exports each character as a
28×28 binary image. It also *rejects* regions that do not look like a plate (character count
outside [5, 9], inconsistent heights or baseline), which is the mechanism that filters the
detector's false positives.

**3 · OCR** (`alpr/ocr/`) — `CharCNN`, a compact convolutional network (831,332 parameters,
36 classes: A–Z and 0–9) trained from scratch on 18,000 synthetic images rendered from 19 fonts
and degraded with geometric, stroke and contour augmentation.

**3b · Reader** (`alpr/reader/`) — assembles the final string. It applies **no** contextual
correction: the plates in this dataset follow no fixed pattern (5–9 characters from any European
country, in arbitrary order), so there is no way to know which direction to correct an
`O`↔`0` confusion in.

## Installation

Requires Python 3.12+. With [uv](https://docs.astral.sh/uv/):

```bash
uv sync
```

Or with pip:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Usage

Run from the repository root (the `alpr` package is imported as `from alpr import config`):

```bash
python main.py --input data/raw/car.jpg
```

```bash
python main.py --input data/raw/ --output output/results.csv
```

| Argument | Required | Description |
| --- | :---: | --- |
| `--input` | yes | Path to an image or a directory of images |
| `--output` | no | CSV file to write the results to |
| `--model` | no | Path to the OCR checkpoint (default: `models/char_cnn_best.pth`) |
| `--debug` | no | Print intermediate stages and open OpenCV windows |
| `--show` | no | Display the annotated result |
| `--verbose` | no | Enable DEBUG-level logging |

Supported image formats: `.jpg`, `.jpeg`, `.png`, `.bmp`, `.tif`, `.tiff`.

The CSV output looks like:

```csv
file,plate,n_chars,mean_conf,box
eu1.jpg,M5XSX,5,1.0000,"(120, 80, 210, 45)"
```

## Training the OCR from scratch

The trained checkpoint (`models/char_cnn_best.pth`) is not tracked in this repository. To
regenerate it, run the four steps in order:

```bash
python notebooks/ocr/01_render_fonts.py    # render 36 classes from resources/fonts/*.ttf
python notebooks/ocr/02_augment.py         # degrade + resize to 28x28 → data/synthetic/{train,val}
python notebooks/ocr/03_train_cnn.py       # train → models/char_cnn_best.pth
python notebooks/ocr/04_evaluate_real.py   # evaluate on real segmented characters
```

These are sequential stages of one process, not alternatives. Step 2 ends with exactly the same
adaptive threshold the segmenter applies at inference time, so that the edge texture the network
sees during training matches the real one.

## Reproducing the results

```bash
python scripts/evaluate_detector.py                      # detector recall
python -m alpr.ocr.eval_real                             # char/plate accuracy + confusion matrix
python scripts/experiments/error_attribution.py          # per-stage error attribution
python scripts/experiments/compare_detectors.py          # morphological vs Harris vs Canny
python scripts/experiments/ablate_segmenter.py           # contours vs projection; vj vs regla-or
python scripts/experiments/ablate_pipeline.py            # NORM_H and deskew ablations
python scripts/experiments/sweep_detector.py             # detector threshold sweep
python scripts/experiments/export_analysis.py            # tidy CSVs for analysis
python scripts/experiments/plot_analysis.py              # analysis figures
```

Results are written to `output/experiments/` and `models/`.

### Design decisions validated by measurement

| Decision | Alternative | Result |
| --- | --- | --- |
| Morphological detector | Harris + density map · Canny multiscale | 98.1 % vs 82.4 % · 73.1 % recall |
| Segmentation by contours | Vertical projection | 88 vs 33 valid ROIs |
| `vj` character format | `regla-or` (64×64 canvas) | 73.69 % vs 38.56 % char accuracy |
| Normalisation to 96 px | 32 / 48 / 64 / 128 / 160 px | best plate accuracy (31.8 %) |
| Deskew by centroid regression | `minAreaRect` · none | +4 accepted ROIs, best plate accuracy |

The `vj` result is deliberately counter-intuitive: theory suggested reproducing the training
canvas, but direct measurement showed the simple resize almost doubles character accuracy.

## Known limitations

- **Segmenter robustness.** It rejects about one in four real plates and mis-counts characters on
  another quarter, mostly because of the blue EU band and merged blobs. This is the main
  bottleneck.
- **Domain gap.** The CNN trains on clean synthetic glyphs and infers on degraded photographs;
  the most frequent confusions are `0→O` and `1→7`. The network is also overconfident: incorrect
  predictions still carry a median confidence around 0.96, so a confidence threshold alone does
  not filter them.
- **Very small plates.** Plates as small as 18 px carry little information; scale normalisation
  helps but does not fully compensate.
- **No fixed plate format**, so the reader cannot validate or correct a reading by position.
